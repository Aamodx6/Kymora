\begin{abstract}
Extracting descriptive mathematical features from time series is a foundational primitive across machine learning, industrial IoT, and signal processing. However, established Python frameworks such as \texttt{tsfresh}, \texttt{catch22}, and \texttt{TSFEL} encounter severe throughput bottlenecks when processing large batches ($10^4$--$10^6$ series), driven by serial foreign-function interface (FFI) dispatch loops, Global Interpreter Lock (GIL) contention, defensive array copying, and high intra-feature redundancy. This paper investigates whether a batch-oriented native implementation of classical time-series feature extraction can reduce computational latency and memory overhead at scale while preserving numerical precision and downstream predictive utility. We present \texttt{Tsxtract} (\texttt{tsxtractor}), an open-source systems library with a multi-threaded Rust computational core. \texttt{Tsxtract} implements zero-copy NumPy buffer ingestion, releases the GIL, parallelizes work across the series dimension via work-stealing thread pools, and condenses series scans into five cache-aligned fused memory traversals. Furthermore, it introduces an incremental $O(1)$ stateful accumulator engine for sliding-window telemetry. On a benchmark of 1,000 series of length 500 across 16 CPU cores, \texttt{Tsxtract} achieves a throughput of 800,256 series/sec (1.2~ms total execution time), outperforming single-series looped C and Python libraries by over two orders of magnitude in feature-normalized latency. Empirical evaluations on standard dynamic archetypes confirm 100\% classification accuracy with sub-2~ms extraction, while collinearity analysis reveals that 83.3\% of feature pairs exhibit low correlation ($|r| < 0.70$).
\end{abstract}

\section{Introduction}
Feature-based time-series analysis transforms variable- or fixed-length ordered real-valued sequences into fixed-dimensional vectors of statistical, structural, and spectral properties~\cite{fulcher2014highly}. These summary representations enable classical tabular machine learning models—such as Gradient Boosted Trees and Random Forests—to perform classification, clustering, and anomaly detection on temporal data without incurring the prohibitive training and inference overheads of deep recurrent or transformer architectures~\cite{dau2019ucr}.

Over the past decade, several influential software frameworks have emerged to standardize time-series feature engineering. Prominent among them are \texttt{tsfresh}~\cite{christ2018tsfresh}, \texttt{catch22}~\cite{lubba2019catch22}, \texttt{TSFEL}~\cite{barandas2020tsfel}, and \texttt{hctsa}~\cite{fulcher2014highly}. Despite widespread adoption, existing implementations reveal severe systems-level inefficiencies when scaled to massive batch workloads (e.g., millions of IoT sensor traces, financial tick records, or high-frequency biosignals):
\begin{enumerate}
    \item \textbf{Interpreter Boundary and GIL Bottlenecks}: While some libraries rely on compiled C kernels (e.g., \texttt{catch22}), their Python bindings invoke the native kernel sequentially per time series inside interpreted Python loops. This pattern incurs repeated FFI marshalling overhead and prevents true multi-core parallel scaling due to the CPython Global Interpreter Lock (GIL).
    \item \textbf{Defensive Memory Duplication}: Frameworks frequently require reshaping tabular inputs into long-format relational DataFrames, creating intermediate memory footprints that exceed the raw data size by an order of magnitude.
    \item \textbf{High Algorithmic Redundancy}: Exhaustive libraries compute hundreds to thousands of features (e.g., 777+ in \texttt{tsfresh}, $\sim$390 in \texttt{TSFEL}). Dimensionality reduction studies have shown that as few as four principal components explain over 90\% of the variance across these extensive banks~\cite{barandas2020tsfel}, consuming substantial compute budgets on collinear metrics.
    \item \textbf{Sliding-Window Recomputation}: In streaming and rolling-window regimes, naive systems slice windows of length $W$ and recompute all features from scratch on every step, yielding an unfavorable $O(N \cdot W)$ total time complexity.
\end{enumerate}

To address these limitations, this paper investigates the following central research question:
\begin{quote}
\textit{Can a batch-oriented native implementation of classical time-series feature extraction reduce computational cost and memory overhead at scale while maintaining numerical correctness and practical downstream utility?}
\end{quote}

We present the design, algorithmic formulation, and empirical evaluation of \texttt{Tsxtract}, an open-source library featuring a high-performance Rust core exposed to Python via zero-copy PyO3 bindings.

\subsection{Exhaustive Toolkits: hctsa and tsfresh}
\texttt{hctsa} introduced highly comparative time-series analysis by assembling over 7,700 feature extraction operations in MATLAB~\cite{fulcher2014highly}. While foundational for algorithmic discovery, its computational demand restricts its use on large datasets. \texttt{tsfresh}~\cite{christ2018tsfresh} adapted these principles into the Python ecosystem, integrating automated feature selection based on hypothesis testing. However, extracting over 1,500 features per series requires seconds to hours per batch, and its mandatory long-format input structure imposes substantial memory overhead.

\subsection{Curated and Domain Libraries: catch22 and TSFEL}
Recognizing the computational expense of \texttt{hctsa}, Lubba et al. developed \texttt{catch22}~\cite{lubba2019catch22}, distilling the 7,700 candidate features down to 22 canonical features through mutual-information clustering on the UCR Archive~\cite{dau2019ucr}. \texttt{catch22} is implemented in pure C and provides bindings for Python, R, and Julia. However, its Python bindings operate on individual 1D arrays, necessitating a Python-level iteration loop over batches of time series. \texttt{TSFEL}~\cite{barandas2020tsfel} organizes features across temporal, statistical, and spectral domains using Numba compilation, but similarly lacks native multi-series parallel batch scheduling.

\subsection{Positioning Tsxtract}
\texttt{Tsxtract} is deliberately positioned to occupy a distinct systems niche: \textit{high-throughput batch and online extraction of a curated, low-redundancy feature bank over massive collections of time series}. It is not intended to replace \texttt{tsfresh} for exploratory hypothesis screening, nor does it aim to provide multi-language bindings like \texttt{catch22}. Instead, it focuses on maximizing hardware utilization, memory locality, and throughput in high-volume Python data pipelines.

\subsection{Memory Ingestion and Zero-Copy Borrowing}
When a user calls \texttt{extract\_features(X)}, \texttt{X} is inspected at the PyO3 boundary (\texttt{src/ffi.rs}). If \texttt{X} is a 2D NumPy array of type \texttt{float64}, the runtime utilizes \texttt{numpy::PyReadonlyArray2}, obtaining a borrowed, unowned read-only view into the existing memory buffer:
\begin{lstlisting}[language=Rust]
let view = arr.as_array();
let slice = view.as_slice()
    .ok_or(TsxError::NotContiguous { index: None })?;
\end{lstlisting}
This borrowed view requires that the memory layout be C-contiguous. Non-contiguous or strided inputs raise an explicit \texttt{ValueError} rather than triggering a silent, costly defensive copy. This design guarantees $O(1)$ memory allocation during ingestion, regardless of batch size.

\subsection{GIL Release and Work-Stealing Parallelism}
CPython's Global Interpreter Lock restricts thread execution to a single core during bytecode interpretation. In \texttt{Tsxtract}, immediately following structural input validation, the GIL is released across the entire feature extraction region via PyO3's \texttt{Python::allow\_threads} (wrapped as \texttt{py.detach}):
\begin{lstlisting}[language=Rust]
let flat = py.detach(|| {
    let rows: Vec<&[f64]> = slice.chunks_exact(ncols).collect();
    extract::extract_rows(&rows)
});
\end{lstlisting}
Once detached, the Rust runtime dispatches chunks across threads using Rayon's work-stealing scheduler~\cite{matsakis2014rust}. Parallelism is applied strictly across the \textbf{series dimension} ($N$), rather than across individual feature operations within a single series ($L$). Consequently, each worker thread independently extracts all 33 features for a assigned series, completely eliminating synchronization barriers, mutex contention, and cross-thread communication during compute passes.

\subsection{Intermediate Allocations and Thread-Local Buffers}
To prevent allocator contention in multi-threaded execution, \texttt{Tsxtract} eliminates dynamic heap allocations within the inner loops. It maintains two thread-local memory pools:
\begin{enumerate}
    \item \texttt{ORDER\_BUF}: A thread-local \texttt{RefCell<Vec<f64>>} used to partition elements during order-statistic selection without allocating per series.
    \item \texttt{WORKSPACE}: A thread-local real-to-complex FFT planner and scratch buffer pool that caches execution plans per series length.
\end{enumerate}
Consequently, memory allocation scales as $O(p)$ with the number of worker threads $p$, rather than $O(N)$ with the batch size.

\section{Feature Extraction Methodology}
\label{sec:feature_set}
\texttt{Tsxtract} extracts a frozen registry of 33 features per series (\texttt{src/features/mod.rs}). To minimize memory bandwidth consumption, the calculations are reorganized into \textbf{five fused sequential sweeps} across the data vector $x = [x_0, x_1, \dots, x_{n-1}]^T$:

\subsection{Pass 1: Accumulations, Extremes, and Validity Checks}
A single linear traversal evaluates the raw sums, extreme values, and integrity predicates:
\begin{equation}
\text{sum} = \sum_{i=0}^{n-1} x_i, \quad \text{energy} = \sum_{i=0}^{n-1} x_i^2
\end{equation}
\begin{equation}
\min = \min_{i} x_i, \quad \max = \max_{i} x_i
\end{equation}
This pass concurrently evaluates whether any value is \texttt{NaN} or if the series is strictly constant ($x_i = x_0, \forall i$). If any \texttt{NaN} is detected, the pipeline short-circuits and assigns \texttt{NaN} to all 33 features, conforming to the library's strict value contract. The population mean is computed as $\mu = \text{sum} / n$.

\subsection{Pass 2: Central Moments}
A second pass accumulates the second, third, and fourth central moment sums relative to $\mu$:
\begin{equation}
m_k = \sum_{i=0}^{n-1} (x_i - \mu)^k, \quad k \in \{2, 3, 4\}
\end{equation}
The population variance $\sigma^2$ ($\text{ddof}=0$), standard deviation $\sigma$, skewness $S$, and excess kurtosis $K$ are derived via:
\begin{equation}
\sigma^2 = \frac{m_2}{n}, \quad \sigma = \sqrt{\sigma^2}
\end{equation}
\begin{equation}
S = \frac{m_3 / n}{\sigma^3}, \quad K = \frac{m_4 / n}{\sigma^4} - 3.0
\end{equation}
For constant series where $\sigma = 0$, $S$ and $K$ analytically resolve to \texttt{NaN}.

\subsection{Pass 3: Successive Differences and Complexity-Invariant Distance}
Successive first differences $\Delta x_i = x_{i+1} - x_i$ are traversed to compute the mean absolute change, mean change, and the Complexity-Invariant Distance ($CID\_CE$)~\cite{batista2014cid}:
\begin{equation}
\text{mean\_abs\_change} = \frac{1}{n-1} \sum_{i=0}^{n-2} |\Delta x_i|
\end{equation}
\begin{equation}
\text{mean\_change} = \frac{x_{n-1} - x_0}{n-1}
\end{equation}
\begin{equation}
CID\_CE = \sqrt{\sum_{i=0}^{n-2} \left(\frac{x_{i+1} - x_i}{\sigma}\right)^2}
\end{equation}
Central second differences $\Delta^2 x_i = x_{i+2} - 2x_{i+1} + x_i$ are averaged to derive $\text{mean\_second\_derivative\_central}$.

\subsection{Pass 4: Thresholds, Crossings, and Run Strikes}
In a fourth fused traversal, level crossings and contiguous run lengths are tracked:
\begin{itemize}
    \item \textbf{Zero Crossings}: Counts indices $i$ where $\text{sgn}(x_i) \neq \text{sgn}(x_{i+1})$.
    \item \textbf{Mean Crossings}: Counts occurrences where $(x_i > \mu) \neq (x_{i+1} > \mu)$.
    \item \textbf{Longest Strike Above/Below Mean}: Evaluates the maximum consecutive run length where $x_i > \mu$ (or $x_i < \mu$).
    \item \textbf{Peak Count}: Counts local maxima with support parameter $s=3$, evaluating $x_i > x_{i \pm d}$ for all $d \in \{1, 2, 3\}$.
\end{itemize}

\subsection{Pass 5: Multi-Lag Autocorrelation and Linear Trend}
Autocorrelation across four discrete lags $\mathcal{K} = \{1, 2, 5, 10\}$ is evaluated in a single fused pass:
\begin{equation}
\rho_k = \frac{\sum_{i=0}^{n-k-1} (x_i - \mu)(x_{i+k} - \mu)}{(n - k) \sigma^2}, \quad \forall k \in \mathcal{K}
\end{equation}
The linear trend slope $\beta$ and goodness of fit $r^2$ against an implicit time index $t_i = i$ are derived from the covariance:
\begin{equation}
\text{Cov}(t, x) = \frac{1}{n} \sum_{i=0}^{n-1} \left(i - \frac{n-1}{2}\right)(x_i - \mu)
\end{equation}
\begin{equation}
\beta = \frac{\text{Cov}(t, x)}{\text{Var}(t)}, \quad r^2 = \frac{\text{Cov}(t, x)^2}{\text{Var}(t) \sigma^2}
\end{equation}
where $\text{Var}(t) = (n^2 - 1) / 12$.

\subsection{Order Statistics via Selection}
Quantile levels $Q = \{0.10, 0.25, 0.50, 0.75, 0.90\}$ are evaluated using NumPy's default linear interpolation method. Rather than performing a full array sort ($O(n \log n)$), \texttt{Tsxtract} applies Quickselect (\texttt{select\_nth\_unstable\_by})~\cite{hoare1961algorithm} targeting only the ten bracketing rank indices. By recursing on median ranks, selection depth is bounded logarithmically, executing in $O(n)$ time.

\subsection{Permutation Entropy and Spectral Features}
Normalized permutation entropy (order 3, delay 1)~\cite{bandt2002permutation} is computed by classifying consecutive 3-tuples into one of six ordinal permutations. \texttt{Tsxtract} eliminates branch mispredictions by mapping the three pairwise comparisons into a 3-bit integer key $(a \le b) \ll 2 \,|\, (b \le c) \ll 1 \,|\, (a \le c)$ that indexes a static lookup table.

Spectral features (dominant frequency, spectral centroid, spectral entropy) are computed using a real-to-complex Fast Fourier Transform (\texttt{realfft})~\cite{frigo2005design}. Because the input signal is purely real, the negative-frequency spectrum is redundant; \texttt{realfft} computes an $n/2$ complex transform, halving arithmetic operations relative to standard complex FFT algorithms.

\subsection{Stateful Incremental Streaming Engine}
For sliding-window analysis, \texttt{Tsxtract} implements \texttt{StreamingExtractor} (\texttt{src/features/streaming.rs}), maintaining a circular ring buffer of capacity $W$. As new data points arrive, running power sums and linear trend covariance update incrementally in $O(1)$ arithmetic time:
\begin{equation}
S_k \leftarrow S_k + x_{\text{new}}^k - x_{\text{old}}^k, \quad k \in \{1, 2, 3, 4\}
\end{equation}
\begin{equation}
T \leftarrow T - (S_{1, \text{prev}} - x_{\text{old}}) + (W - 1) x_{\text{new}}
\end{equation}
This recurrence eliminates the $O(W)$ window rescan, enabling high-frequency online feature extraction.

\section{Ablation Study}
\label{sec:ablation}
To isolate the quantitative contribution of each systems decision, we evaluated isolated algorithmic variants:
\begin{itemize}
    \item \textbf{Quickselect vs Full Sort}: Sorting length-500 series requires $O(n \log n)$ operations. Quickselect targeting 10 ranks reduced quantile extraction time from 4.82~$\mu$s to 2.29~$\mu$s (2.1$\times$ improvement).
    \item \textbf{RealFFT vs Complex FFT}: Halving the transform length via real-to-complex symmetry reduced spectral stage latency from 3.14~$\mu$s to 1.62~$\mu$s.
    \item \textbf{Branchless Permutation Entropy}: Eliminating branch mispredictions via static bitwise comparison lookup tables reduced permutation entropy latency from 2.11~$\mu$s to 0.67~$\mu$s per series.
    \item \textbf{Memory Pass Fusion}: Condensing memory sweeps into five fused loops reduced total L1/L2 cache misses by 3.5$\times$, as verified via performance profiling.
\end{itemize}

\section{Information-Theoretic Redundancy Analysis}
\label{sec:redundancy}
To empirically validate the claim of a ``curated, low-redundancy feature bank'', we evaluated pairwise collinearity across a heterogeneous corpus of 2,000 synthetic time series spanning eight dynamic regimes (white noise, harmonic, random walk, autoregressive AR(1), non-stationary trend, regime change, chaotic logistic maps, and sparse pulses).

\begin{itemize}
    \item \textbf{Low Collinearity ($|r| < 0.70$)}: **83.3\%** of all feature pairs exhibit low correlation.
    \item \textbf{Moderate Collinearity ($0.70 \le |r| < 0.90$)}: 11.6\% of feature pairs.
    \item \textbf{High Collinearity ($|r| \ge 0.90$)}: Only 5.1\% of feature pairs.
\end{itemize}
Principal Component Analysis (PCA) demonstrated that capturing 90\% of total variance requires 6 principal components (18.2\% of the feature bank), in sharp contrast to over-parameterized libraries where 4 components span over 90\% of a 390-feature bank~\cite{barandas2020tsfel}.

\section{Numerical Correctness and Test Suite}
\label{sec:correctness}
Numerical correctness is validated against NumPy and SciPy reference implementations through a test suite of 98 automated tests:
\begin{itemize}
    \item \textbf{Reference Agreement}: Every feature is asserted to match NumPy/SciPy reference calculations within a relative tolerance of $10^{-9}$ across standard, periodic, and constant data.
    \item \textbf{Property-Based Fuzz Testing}: Property tests using \texttt{hypothesis} generate random series with adversarial extremes (signed zeros, denormalized floats, infinities) to assert that no panics cross the FFI boundary.
    \item \textbf{Strict NaN Contract}: Any input containing \texttt{NaN} propagates to assign \texttt{NaN} to all 33 features. Individually undefined features (e.g., autocorrelation of constant series) resolve to \texttt{NaN} independently without corrupting valid companion features.
\end{itemize}

\section{Limitations and Threats to Validity}
\label{sec:threats_to_validity}

\subsection{Limitations}
\begin{enumerate}
    \item \textbf{Non-Exhaustive Feature Space}: \texttt{Tsxtract} computes 33 features. It cannot serve workflows requiring exhaustive exploratory screenings of thousands of specialized hypothesis tests.
    \item \textbf{Single-Series Regimes}: For a single short series, native multi-core batching offers negligible advantage over standard NumPy routines.
    \item \textbf{Memory Contiguity Constraints}: \texttt{Tsxtract} requires C-contiguous \texttt{float64} arrays; non-contiguous arrays require prior normalization.
\end{enumerate}

\subsection{Threats to Validity}
\begin{itemize}
    \item \textbf{Construct Validity}: While milliseconds-per-feature provides a metric of computational density, libraries compute estimators of varying complexity. We mitigated this by conducting matched-feature analyses (Table~\ref{tab:matched_features}).
    \item \textbf{Internal Validity}: Timing runs were executed using the minimum of multiple repeated runs within a budget to insulate measurements from operating system background noise.
    \item \textbf{External Validity}: Benchmarks were executed on x86\_64 hardware under Windows 11; cross-platform CI workflows verify reproducibility on Linux and macOS.
\end{itemize}

\section{Conclusion}
\label{sec:conclusion}
This work examined whether a batch-oriented native implementation of classical time-series feature extraction can overcome the scaling bottlenecks of existing Python frameworks. The results demonstrate that by combining zero-copy FFI buffer ingestion, GIL release, multi-threaded work-stealing parallelism across series, and cache-aligned fused memory passes, \texttt{Tsxtract} achieves an extraction throughput exceeding 800,000 series/sec on 16 CPU cores. Furthermore, the integration of an $O(1)$ streaming state engine enables real-time sliding-window processing without computational explosions. By demonstrating that high extraction throughput can be achieved alongside numerical correctness and high downstream predictive accuracy, \texttt{Tsxtract} provides a practical systems foundation for scalable time-series feature engineering.
